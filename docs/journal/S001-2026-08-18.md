`Tsudev.Audit.Core` build **thành công**. `Tsudev.Audit.Windows` cũng build được
— nghĩa là gói NuGet `System.Management` restore ổn, và `net8.0-windows`
biên dịch được trên Linux đúng như phán đoán.

**Quyết định & lý do:**

1. **Tập trung version vào `Directory.Build.props`**, xoá `<Version>`,
   `<Company>`, `<Product>`, `<Description>` khỏi `Cli.csproj`. Lý do: sắp tới
   sẽ có thêm installer và winget manifest cùng cần số hiệu phiên bản — nếu để
   rải rác thì chắc chắn có ngày lệch nhau.
2. **Chưa tách file gộp nhiều class thành file riêng.** Chỉ đổi chỗ file là đủ
   để build. Việc tách nhỏ là chỉnh trang, và làm nó trước khi có test xanh là
   tự chuốc rủi ro không cần thiết → dời sang Phase 4.
3. `RunAnalyzers=false` cho project test — bộ test dùng top-level statements,
   phân tích CA ở đó chỉ tạo nhiễu.

**Vấn đề đã gặp:** `dotnet sln add` từ chối `unittests.csproj` với lỗi
*"An XML comment cannot contain '--'"*. Nguyên nhân: comment trong csproj có
chuỗi `dotnet run --project`. Cách gỡ: viết lại comment không dùng dấu `--`.
Đây là bẫy dễ vấp khi viết comment chứa tham số dòng lệnh trong file XML.

**Nợ đã ghi nhận:** build Core sinh khoảng 25 cảnh báo CA1305 (ToString không
truyền IFormatProvider) và CA1826. Chưa sửa — sẽ xử lý gọn ở Phase 4 kèm
`.editorconfig`, vì CA1305 ở đây phần lớn vô hại nhưng vẫn nên chuẩn hoá.
